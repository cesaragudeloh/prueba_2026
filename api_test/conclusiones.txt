Hallazgos y conclusiones del ejercicio

## Solución Final

Se implementó un flujo CRUD completo en Karate que garantiza **orden estricto** y **reutilización del mismo usuario**:

### Flujo implementado (crud-flow.feature)
1. **Paso 1: Crear usuario** → POST /user (status 200)
2. **Paso 2: Buscar usuario creado** → GET /user/{username} (valida datos originales)
3. **Paso 3: Actualizar nombre y correo** → PUT /user/{username} (status 200)
4. **Paso 4: Buscar usuario actualizado** → GET /user/{username} (valida cambios)
5. **Paso 5: Eliminar usuario** → DELETE /user/{username} (status 200)
6. **Validación: Confirmar eliminación** → GET /user/{username} (status 404)

### Decisiones de diseño
- **Un solo scenario** con 5 pasos claramente separados por comentarios.
- **Mismo usuario** reutilizado en todos los pasos (userId y username generados una sola vez).
- **Fin del parámetro único** para evitar conflictos: cada ejecución crea usernames únicos con UUID.
- **Plantilla reutilizable** (user.json) con datos sintéticos para mantener limpieza de código.
- **Ejecución secuencial** (parallel=1) para estabilidad con el servicio público.

### Validaciones del Petstore
- POST /user: responde 200 con confirmación
- GET /user/{username}: retorna el usuario con todos los campos
- PUT /user/{username}: actualiza datos, mantiene username
- DELETE /user/{username}: retorna 200 con confirmación
- GET posterior a DELETE: retorna 404 "User not found"
